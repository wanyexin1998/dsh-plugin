# BOOP 隐私与数据边界（准备版）

> 状态：**准备材料**，基于当前实现与已提交证据（2026-10-18）。发布前需随实现变更复核；
> 真实用户环境的网络抓包/日志审计为 `NOT_RUN`。

## 1. 一句话

BOOP 是**本地优先**插件：数据默认只存在本机 `$DSH_HOME` 下的 BOOP 自有账本里，
不收集遥测、不连接任何 BOOP 自有服务器；唯一的外发方向是用户自己在 DSH 里配置的模型服务
（以及用户显式启用后的 IM 渠道，当前默认关闭）。

## 2. 数据存在哪里

| 位置 | 内容 |
|---|---|
| `$DSH_HOME\boop\boop.sqlite` | BOOP 自有 SQLite 账本（WAL、单写者租约） |
| `$DSH_HOME\boop\backups\*`（若执行过迁移/备份） | 迁移前一致备份 |
| DSH 原生数据目录 | 主聊天/任务 Session 日志、原生工作区注册；由 DSH 管理，BOOP 不复制其全文 |

`$DSH_HOME` 默认 `~/.dsh`（Windows `C:\Users\<你>\.dsh`）；可用环境变量覆盖。
账本 `scopeId` 由规范化 `$DSH_HOME` + 本地 owner 派生，不读取用户名以外的外部标识。

## 3. 账本里实际存了什么

- 任务：目标文本、验收标准、禁止项、三轴状态、版本、时间。
- 动作/审批：目标 Session id、载荷哈希、**派发指令文本**、模式、状态、消息 id、
  taskVersion、policyEpoch、审批绑定（payloadHash/taskVersion/policyEpoch/owner/nonce 绑定值/有效期/状态）。
  —— 指令文本会被保存，因为审批与对账必须绑定"用户实际看到/批准的那条命令"。
- 审计：actor、事件类型、对象 id、原因、时间（例如 `control/approval-decided`）。
- 记忆：事实文本与权威级别、证据**地址**（sessionId、seq、sourceHash、artifactRef）、
  聚合快照文本与覆盖范围、读取水位（每个 Session 世代读到哪个 seq）。
- 出站回执：消息 id 等对账信息。

**不存**：模型密钥、渠道凭证（渠道默认关闭且未配置）、完整聊天记录的副本、项目文件的拷贝。
人工记忆提取器在入库前会拒绝疑似密钥内容（`POSSIBLE_SECRET`），模型客户端只接受
`credentialRef`/`env:` 形式的引用、拒绝原始明文密钥（E05-00 证据）。

## 4. 唯一外发边界：模型服务

- BOOP 通过 DSH 已配置的模型路由发送正常对话/上下文（与普通 DSH Session 相同的通道）；
  BOOP **不内置**供应商地址、不猜测上下文长度、不持有凭据。
- 不额外上传账本文件、项目文件或 Session 日志；发送内容就是该次对话/任务所需的上下文。
- 模型不可用时如实报错，**不静默切换**到其他供应商；没有云同步、没有 BOOP 自有服务器。
- 用户更换模型路由 = 更换该外发边界；BYO 模型服务的日志/留存策略由服务提供方决定。

## 5. 日志与遥测

- **不收集遥测/分析数据**；插件不发起统计上报。
- BOOP 自身日志只写装配状态、能力/门账本事实、对象 id 与错误原因；按实现不写对话正文。
  DSH 宿主自身的 Session 日志与诊断由 DSH 管理并保存在本地。
- 公开仓库中的证据必须脱敏：本仓库已提交证据均为**合成数据/隔离 DSH_HOME**，
  不含真实对话或凭证；截图在公开发布前须检查浏览器/桌面内容。

## 6. 渠道（钉钉/飞书）

默认关闭；未配置凭证时不会建立任何出站连接（G07 仍 `NOT_RUN`）。用户显式启用并完成绑定后，
消息会经对应平台收发；平台侧的隐私条款由平台决定。第一版不默认把项目内容发到群聊。

## 7. 用户可控

- 停止/停用插件：见 `uninstall.md`（默认保留数据）。
- 删除本地数据：备份后删除 `$DSH_HOME\boop\`（只删 BOOP 自有账本）。
- 关闭/更换模型路由：在 DSH 设置中操作，BOOP 跟随。
- 不启用渠道即无渠道外发。

## 8. 未验证（NOT_RUN）

- Desktop Electron 进程内日志内容审计。
- 渠道启用后的端到端隐私行为（渠道默认关闭，M2 才联调）。
- 第三方安全/隐私专项评审。
