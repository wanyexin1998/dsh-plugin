# BOOP 前端设计方案

> 版本：1.1 · 目标：DSH Web 与 Desktop 0.2.0-rc.2  
> 本册给出信息架构、逐屏行为和组件规范。已有框架 HTML 是概念导览，不是生产 UI 模板；本包阅读器也不是运行中的插件。

## 01｜前端设计目标

让用户感觉“原来的 DSH 多了一位知道全局的助理”，而不是“安装插件后 DSH 变成另一个应用”。对话优先，有事才出现任务；任务和审批可持续存在，但不制造独立通知中心。

默认保持原生侧栏、原生输入、原生 Session 历史、原生右侧栏和明暗主题。只增加固定 BOOP 身份入口、主 Session 的局部扩展、轻量看板及原生设置项。

## 02｜原生接入方案

| 位置 | 接入策略 | 作用范围 |
|---|---|---|
| 左侧 BOOP 入口 | 使用已核验 sidebar 贡献点或原生置顶 Session；准确 slot 由 G09 验证 | 不替换整个 sidebar |
| BOOP 主页面 | 导航到已绑定主 Session，直接用原生 Conversation | 主 Session 专属装饰 |
| 主聊天头部 | BOOP 名字、小头像、连接状态、任务入口 | 不覆盖普通 Session 头部 |
| 会话中的任务/审批卡 | BOOP 自定义工具呈现或已核验消息扩展位 | 必须保留 native message/source 关联 |
| 任务看板 | 注册独立 `main` key，例如拟定 `boop.tasks` | root-scoped 全局面板，不使用保留 `conversation` key |
| 设置 | 原生设置扩展项 BOOP | 不替换 General、Models、Plugins 等页面 |
| 原 Session 回跳 | 原生导航与 Session reference | 不造第二套 Session 页面／分屏 |

rc.2 的 `layout.selectPanel(id)` 会验证已注册 key；`null` 可回到 Conversation 而不改变选中 Session。Conversation 已承载输入状态、队列与组件扩展；同一 Session 不支持同时挂两个可编辑根，因此主页面不再嵌入一个平行输入框。[S05][S06]

不依赖 DOM 查询选择器去隐藏原生按钮，不依据 CSS class 片段复制 nanoMuse 外观。非稳定钩子的维护风险在 nanoMuse 专门的检查脚本里已有说明。[S20]

## 03｜页面地图与导航

```text
固定入口 BOOP
    └─ 主聊天（默认）
        ├─ 查看任务 → 任务看板 → 返回主聊天
        ├─ 任务卡 → 任务详情抽屉（同一页，不新聊天）
        ├─ 证据 → 原 Session 精确位置 → 回到 BOOP
        └─ 设置 → 原生 BOOP 设置项
```

导航携带 returnContext：mainSessionId、taskId、draft owner、scroll anchor、打开前的面板。返回不重新发送消息、不重复审批、不重置输入。不自动打开浏览器新窗口；外部来源仅由用户点击打开，并标明外部网站。

主动事件绝不抢夺当前原 Session 的页面。主聊天有新消息时也不直接跳转用户正在看的工作区。

## 04｜S01：初次进入与模型接通

### 首屏内容

头像与“BOOP · 波波”固定在头部，主文案一条：

> 我会在这里帮你管理 DSH 项目。先选一种记忆起点：从现在开始、学习已有会话，或导入你的记忆。

三个按钮位于同一条初始化消息中，不弹全屏 onboarding。模型未配置时，显示“先连接你的模型”，打开原生模型配置/BOOP 路由选择，不要求新注册账号。

### 初始化选项

| 操作 | 下一步 | 成功回执 | 失败与退出 |
|---|---|---|---|
| 从现在开始 | 设置水位，轻量列目录 | “已从此刻开始记录。旧历史没有自动导入。” | 配置失败不写完成；可重试 |
| 学习已有会话 | 显示项目范围与排除入口，默认已授权范围 | “已开始整理；不会恢复历史任务。” | 可暂停；失败对象单独列示 |
| 导入记忆 | 文件选择/文本粘贴 → 校验预览 → 确认 | 说明新增、重复、待核查数量 | 不支持格式明确拒绝，不执行文件 |

历史进度卡只更新原卡的投影，不每处理一个 Session 插一条消息。进度基于处理量，标题用“已整理 12/40 个会话”，不能用“已理解 30% 的项目”。选择可在设置中补充历史学习，不破坏原始选择记录。

## 05｜S02：日常主聊天

```text
[蓝鲸] BOOP · 波波                 模型已连接   [任务]
────────────────────────────────────────────────────
你：把分屏按最新方案继续推进，不要部署。

BOOP：我会沿用原开发会话，完成实现和窄屏检查；不部署。
[分屏开发 · 已接受委托] [查看原 Session]

                   ……原生聊天历史……

[原生输入框；保留附件、IME、发送、队列和 Stop 行为]
```

不持续显示“管理了30个会话”“节省了多少Token”等仪表盘。没有待决事项时保持安静。头部状态只表达连接/运行真实情况，不用“正在努力”替代具体状态。

输入保持原生 Enter/Shift+Enter/互补发送规则，不覆盖终端或输入法快捷键。普通 Session 的 busy queue/steer 配置不被 BOOP 修改。[S06]

每条主动消息有明确任务名和类型，不能插入一段无关结果后让“继续”隐式指向它。后台消息只用 polite 方式标记，不抢键盘焦点。

## 06｜S03：任务看板

**v1.1来源更新：** 看板选择性复用dashi-taskboard的BoardColumn、TaskCard、筛选/列表/拖拽和部分详情交互，不整包嵌入Codex Taskboard。不新增独立HTTP服务、AIChat或第二任务库。具体兼容、许可和验证边界见第06册。[S28][S32][S33][S34]

组件抽取后统一接BOOP Board Adapter；不能保留原组件对独立API、Codex actor、thread恢复命令或未受控附件URL的调用。卡片中的原会话入口改为DSH稳定sessionRef，读取/写入均使用本地owner scope。


默认四个区域：待开始、进行中、待我处理、已结束。它们由任务/执行/验收三轴投影而来，不是数据库另外一份状态。卡片主要信息：任务名、工作区、当前一句状态、最近有效更新、相关Session、待决原因。长标题两行省略但有完整文本入口。

### 卡片操作

| 操作 | 用户结果 | 必要确认 |
|---|---|---|
| 查看详情 | 右侧抽屉或窄屏全页 sheet | 无 |
| 打开原 Session | 定位到目标，保留返回语境 | 多目标时选择，不猜 |
| 暂停 | 停止后续派发，说明当前运行是否仍在收尾 | 正在运行时展示影响 |
| 请求停止执行 | 发停止请求，卡片显示“正在停止” | 明确列出受影响 actions |
| 恢复 | 展示中断后检查结果与目标版本 | 必须用户明确恢复 |
| 结束委托 | 按用户选择结束 | 未验收时用“结束但不标记验收通过” |
| 调整优先级 | 更新排序/后续安排 | 不抢占当前执行 |

首版不提供拖拽到“完成”就伪造验收通过。可支持拖拽排序，但业务状态必须通过明确命令改变。看板可筛选工作区，搜索任务名；不是第二份完整 Session 目录。

## 07｜S04：任务详情

详情顺序：目标与禁止项 → 当前执行/验收 → 需要用户做什么 → 相关 Session → 交付证据 → 简化时间线。默认折叠内部 job、重试和原始参数。

完整字段：taskId、任务版本、来源委托、workspaceRefs、sessionRefs、当前 action、验收标准、证据版本、尚未覆盖、下一步建议、暂停/恢复原因。每个状态可回答“为什么显示这样”。

时间线区分用户变更、BOOP 代理派发、原Agent结果和系统恢复；来源不因都显示为文本而消失。不复制原 Session 全量聊天，点击证据下钻。

## 08｜S05：审批与精确操作

高风险卡必须在首层展示：动作、目标、实际参数摘要、可能影响、是否可逆、批准范围、有效期；可展开完整命令/文件差异。按钮为“批准本次”“拒绝”，拒绝同样容易找到。不使用“信任波波，永久允许”式劝导。

| 状态 | 表现 |
|---|---|
| 等待批准 | 明确对象，两个操作可用 |
| 已批准待执行 | 不称执行成功；展示批准对应版本 |
| 参数或任务变化 | 原卡变为“已失效”，不能再点击 |
| 过期／重启 | “此审批已失效，请重新核查后申请” |
| 拒绝 | 平静确认，不诱导再次批准 |
| 别处已处理 | 同一请求状态同步，操作幂等 |

批量归档先显示候选对象与运行状态；每个对象独立结果。创建工作区注册和创建磁盘目录分别描述。删除项目目录不隐藏在“整理”按钮下。

审批不依赖聊天消息相邻关系。用户说“同意”时，只有唯一、低风险、绑定明确对象的决策可以走确认路径；危险操作要求精确卡片/对象确认。所有卡片按钮发送服务端对象ID和nonce，不回传客户端自称的批准身份。

## 09｜S06：记忆、来源与纠错

不做默认常驻知识库面板。用户问“你怎么知道的”，在回答下显示可展开来源；用户问“记住了什么”，显示对应项目快照、覆盖边界、事实类型。

记忆条目显示：内容、对象、来源类别、有效时间、更新版本、引用入口。个人/项目/Session/管理记忆标签不能仅以颜色区分。

| 情况 | 文案示例 | 用户操作 |
|---|---|---|
| 完整覆盖当前已知记录 | “覆盖至该会话最近一轮” | 查看来源 |
| 落后 | “还未包含最近2轮；操作前会再核查” | 更新/查看最新 |
| 证据缺失 | “来源当前不可读取，结论未重新验证” | 定位原文件 |
| 冲突 | “两条有效记录不一致，尚未选定结论” | 比较原始来源/明确决定 |
| 导入 | “导入记录，尚未与本地项目核实” | 关联工作区/纠正 |
| 遗忘 | “不再使用此条；原聊天仍保留” | 展开影响范围 |

纠错表单默认是一句自然语言与原始来源，不让用户编辑数据库字段。纠正提交后展示正在更新的受影响范围，不立即声称所有执行上下文已被撤回。

## 10｜S07：停止与中断恢复

Stop 的范围必须可见。主输入框 Stop 沿用原生语义，只停 BOOP 当前回答；主聊天头部更多菜单提供“停止全部 BOOP 委托”，以及任务级暂停/终止。全停无需 LLM，但要明确影响对象。

重启后若有中断任务，合并发一条主聊天消息：“2项工作需要恢复，现有文件已保留；尚未继续执行。”展开任务分别确认，不自动全选批准。只读记忆整理恢复不作为业务恢复消息反复通知。

当前状态未知时使用“核查中／结果待确认”，不循环 spinner 假装正在执行。长期查询失败显示可执行的下一步，不把失败写进永久“完成”历史。

## 11｜S08：渠道交互

DSH 主聊天中的外部消息带小标签“来自钉钉／来自飞书”；任务卡显示来源委托渠道，但来源标签不是权限凭据。最终回复回原单聊，不复制其他话题。

绑定在原生设置完成：启用应用配置 → 生成短期绑定码 → 平台本人发送 → 本地确认稳定身份。凭证输入使用密码字段和系统凭证存储，不出现在对话记录。未绑定消息返回最少提示，不泄露项目名。

首版远程高风险审批的回执：“任务 T-012 等待精确审批，请在 DSH 打开该任务确认。”不发送本地 token URL。群聊默认不支持，避免把个人项目内容回给群成员。

## 12｜组件清单与状态机

| 组件 | 必须支持的状态 | 主要行为 |
|---|---|---|
| IdentityEntry | disconnected/idle/working/attention | 固定入口，不闪烁 |
| TaskChip | queued/running/verification/blocked/recovery/ended | 进入同一 Task 详情 |
| ApprovalCard | pending/approved/rejected/stale/expired | 精确确认、幂等点击 |
| CoverageCard | waiting/running/paused/partial/error/done | 初始化同卡投影，不刷屏 |
| EvidenceList | available/stale/missing/redacted | 精确来源跳转 |
| TaskBoard | loading/empty/filtered/partial/stale/error | 分页，错误不显示伪空列表 |
| MainReturn | available/source_gone | 保留 BOOP 草稿、滚动与对象 |
| ChannelBinding | disabled/connecting/unbound/bound/error | 最少权限，明确身份 |

这些组件是 BOOP 局部业务组件，不代表要重写原生 Button、Dialog、Markdown、Composer。优先用原生基础组件和可访问性行为。

## 13｜响应式与桌面窗口

桌面宽屏：聊天仍采用原生宽度，不强行填满；任务看板可四列，详情抽屉宽约400px（设计值）。中等屏幕：看板两列，详情浮层；窄屏≤600px：单列列表、详情全宽sheet，审批按钮可纵排。表格需要独立横向滚动，不让整个页面横溢。

Web 与 Desktop 不是两套不同 UI。macOS 交通灯和 Windows 标题栏需遵循原生 chrome clearance；不得用固定顶距盖住窗口按钮。rc.2 Layout 已提供对应窗口边界和面板几何行为，应复用并测试。[S05]

背景状态更新不移动当前阅读锚点；新消息不抢滚动；打开任务再返回保持草稿。动画使用 reduce-motion 分支；文件选择、浏览器不能完成的原生动作展示能力不可用，不伪装成功。

## 14｜安全渲染与可访问性

模型 Markdown 必须经过宿主安全渲染；禁止任意 HTML/script，远端图片默认不自动加载以避免外发访问与追踪。外链协议白名单；文件引用通过原生已授权读取，不直接把本地任意路径拼成下载URL。

审批和命令参数使用纯文本/代码块，不解释为HTML。来源标签由服务端生成，模型不能伪造“用户已批准”徽章。凭证与私有地址按需要脱敏，展开也需要权限。

键盘：Tab顺序清楚、可见焦点、Esc关闭临时浮层、焦点返回触发器。中文IME过程中 Enter 不误发送。点击目标桌面至少32px、触屏至少44px（本版设计要求）；文字正常对比度以4.5:1为目标，非文本边界3:1，重要状态同时有文案/图标。不能只靠鲸鱼表情表达危险。

## 15｜前端验收清单

FE-01 原生普通Session视觉与工具均不受污染。FE-02 重复点击BOOP只定位同一主会话。FE-03 初始化不抢全屏、不重复发卡。FE-04 看板旧响应不能覆盖新版本。FE-05 证据跳转后返回保留草稿。FE-06 审批参数改变旧卡失效。FE-07 Stop范围准确。FE-08 IME、键盘、触屏可用。FE-09 深浅主题与宿主字号变化可用。FE-10 Desktop窗口按钮不被覆盖。FE-11 断线不是空任务列表。FE-12 停用插件后所有注册和样式清理。

截图回归至少覆盖：1280×800 Web、1440×900 Desktop、390×844窄屏；浅色/深色；普通会话与BOOP主会话；模型离线、审批失效、历史学习部分失败。此处是验收规格，不代表已完成插件浏览器测试。

## v1.1 修订｜视觉与组件来源

原生Conversation保持不变；不将品牌KV大图、细胞体角色或上游Codex侧栏搬到日常聊天。BOOP采用3D KV角色与同形2D小图标两套交付，具体以第05册v1.2及其已确认视觉稿为准。上游卡片CSS需局部作用域化，不原样导入全局reset。

看板默认保留四组投影，任务状态语义不沿用上游单一status直接映射。跨列拖拽第一版关闭；同列排序和键盘/菜单调整优先级可保留。TaskDetail中的评论/附件可裁剪为证据与简化时间线，不新增第二聊天。

验证增加：React18宿主构建、main panel与原Session返回、主题/CSS隔离、动作版本冲突、审批不可旁路、Web/Desktop窗口chrome、键盘操作和非拖拽替代路径。
