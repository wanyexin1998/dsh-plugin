# BOOP 插件完整技术详细方案

> 版本：1.1 · 基线提交：`639ed015397290b3745d163aafe02ffee4aa3f84`  
> 本册是跨文档的技术契约主册。示例接口均属于拟开发 BOOP，不冒充已有 DSH API。附录中的 schema/contract 是设计草案，不是可直接安装的插件。

## 01｜架构原则与适用范围

采用**模块化单体插件**：Host 内一个 BOOP Runtime、一组受控工具与本地数据域，Web/Desktop 共用客户端。模块按职责隔离，不上微服务、Redis、外部向量数据库，也不引入 Python Agent Harness。

只支持已验证的 DSH 0.2.0-rc.2。DSH 原生负责 Session、模型路由、工具执行、原始事件和基础审批；BOOP 自研委托、跨既有 Session 指挥、工作记忆与可靠恢复。DeepSeek-Bot、nanoMuse 与 dashi-taskboard 按模块取材，不作为整包运行依赖。[S01][S02][S07][S14]

用户服务器模型不是 DSH Host：模型持有推理上下文，执行与 BOOP 数据在本地 Host；项目内容会沿已授权网络路径传到模型服务器。插件不部署模型、不猜 URL、不复制密钥。

## 02｜部署边界与数据域

```text
本地 Web 浏览器／DSH Desktop Web 客户端
             │ DSH 已鉴权连接
             ▼
当前 DSH Host 0.2.0-rc.2
  ├─ 原生服务：Agent、Session、Workspace、LLM、Tools、Approval
  ├─ BOOP Host Runtime + BOOP Preset + 自定义工具
  ├─ 可选渠道适配器：钉钉／飞书，仅出站连接或受保护回调
  └─ BOOP 本地数据库与导出
             │ 仅指定模型路由
             ▼
用户自有 Qwen 服务（4bit；196k 容量声明，精确参数待探测）
```

建议数据路径：`$DSH_HOME/boop/scopes/<scopeId>/boop.sqlite`，scopeId 基于规范化 DSH_HOME 与本地 ownerIdentity 生成稳定标识，不能使用外部传入路径拼接。主 Session、任务和记忆都引用 scopeId。

同一数据域一个有效写控制者。Web 与 Desktop 指向同一 Host 时自然共用；同时启动两个 Host 指向同一数据域时，第二个只读，不自动夺取首个 Agent 控制。不同 DSH_HOME 默认隔离，显式迁移后才重建关联。网络共享目录不在 SQLite 写入支持范围，NFS/SMB 上拒绝启用写管理。

使用 `dsh.bundle.patch` 和 `dsh.client` 装配思路，导出 Host/Client 与 Preset。确切包 manifest、peer 声明、client injection 和构建格式必须用 rc.2 安装 smoke 验证后锁定，不复制上游内部 node_modules 代码。BOOP 的 patch 只新增命名空间项，不覆盖全局 persona、默认 Agent preset、搜索提供方、官方 sidebar/settings。

nanoMuse 的整体 Bundle 会替换多个原生外壳和默认设置，BOOP 明确不继承这种全局替换；BOT 也有超出单聊天的装配影响，应按模块裁剪。[S19][S21][S22]

## 04｜上游接口适配矩阵

| 能力 | rc.2 已核验基础 | BOOP adapter 契约 | 验证要求 |
|---|---|---|---|
| Session 创建 | `SessionCreateRequest{workspaceId?,cwd?,sessionId?,agentPreset?}` | ensureMain/createTarget | 精确 Preset；重复初始化不新建 |
| 列举/搜索/历史/投影 | Session Controller 可只读冷历史 | catalog/readHistory/readSnapshot | 不激活原 Agent；跨域拒绝 |
| Prompt 提交 | requestId、queue/steer，返回 accepted | 人类主聊天沿用原生；代理投递另走 source 路径 | 不混淆 accepted 与完成 |
| 代理消息 | BOT 通过 resolveAgent+followup/steer+source | sendCommandEnvelope | SourceMap、messageId、flush、队列回读 PoC |
| 改名/队列/取消 | 对应请求类型存在 | rename/editPending/cancelOwned | itemId 精确匹配，取消范围可解释 |
| 工作区管理 | rc.2 适配器需编译核验原生 Registry | list/create/rename/archive/restore | API 名与移除语义逐方法验证，不直改存储 |
| UI 全局面板 | `main` keyed slot，`layout.selectPanel` | openBoard/backToChat | 不替换 conversation key |
| 主聊天 UI | 原生 Conversation、Session 输入与引用 | decorateMainOnly | 只在 BOOP 绑定 Session 下贡献 UI |
| 事件与取消 | agent-loop/Session 事件模型 | observeNormalizedEvents | 来源白名单、事件水位、停止结算 |
| Schedule | 可选原生能力，本版适配器探测 | bindAutomation | 缺失则显式不可用，不暗造旁路定时写任务 |

上述已核验部分来自 rc.2 文档与源码类型。[S02][S03][S04][S05][S06] 工作区详细补充文档曾按较新提交阅读，只作行为参考，不能替代 rc.2 合约测试。[S27]

**重要版本修正：**本册不假设 rc.2 已有后续提交中的 Peer Principal / Remote Access 策略。BOOP 的接口准入、外部身份映射与对象授权必须自己明确实现在已鉴权宿主入口之上；同进程服务调用不能自动继承远程端点 ACL。

## 05｜Runtime 生命周期与启动顺序

1. 校验 Host 版本、当前数据域、数据目录权限；不相容则仅显示诊断，不启用写能力。
2. 打开 DB、检查 schemaVersion；迁移前做一致性备份，迁移失败保持只读。
3. 获取 scope 级唯一控制 lease；使用递增 fencingToken 防止旧控制者复活写入。
4. **先注册恢复门禁和来源校验，再解析/恢复任何受管 Agent。** 默认禁止上次未结算的 BOOP 命令自动执行。
5. 装配工具、观察器、只读 API 和 UI 服务；用持久化事件补齐退出期间的 gaps。
6. 对账 outbox、native inbox、action 与任务；未知动作保持 outcome_unknown；旧审批过期。
7. 主聊天按用户打开或有效入站消息按需解析；初始化与后台记忆 job 可以继续。
8. 渠道在显式启用后启动；检查 owner binding，再接收业务消息。

退出时停止新派发、停止新后台模型 job，flush BOOP 数据及必要 DSH 接收事实，撤销内存审批句柄，终止连接，释放 lease。已经发生的外部副作用不会因退出回滚。正在执行的原 Agent 按停用策略请求停止并列出未确认部分。

## 06｜数据模型：结构化账本是权威，Markdown 是导出

SQLite 作为初始存储建议，WAL、foreign_keys=ON、单写队列、事务版本控制。`node:sqlite` 是候选 driver；必须验证 Web Node 与 Desktop Electron 内置 runtime 的可用性。备选 driver 会引入 ABI/打包成本，未通过 G08 不宣称跨平台已支持。FTS 是派生索引，禁用 FTS 可降级只读精确查询，不降级安全策略。[S11][S26]

| 表 | 关键字段 | 约束与用途 |
|---|---|---|
| scopes | scope_id, owner_id, main_session_id, policy_epoch, schema_version | 唯一主身份；无密钥 |
| task | id, scope_id, goal, lifecycle, verification, version, criteria_json, exclusions_json | 任务版本 CAS；目标与验收独立 |
| task_revision | task_id, scope_id, version, snapshot_json, intent_ref | 每次委托变更保留不可变快照；动作引用准确版本 |
| task_target | task_id, workspace_id, session_id, role, resource_key | 多工作线关联；不可跨 scope |
| task_dependency | task_id, depends_on | 拒绝环，依赖完成不自动授权 |
| action | id, task_id, task_version, target_session_id, payload_hash, state, message_id, turn_id, policy_epoch | 每次动作有确切版本和来源 |
| command_outbox | action_id, state, attempt, lease_until, receipt_json | 唯一 action；未知不自动重试 |
| ingress | scope_id, channel, tenant_id, event_id, actor_id, state | 组合唯一去重；正文不是 actor 证据 |
| channel_binding | channel, app_id, tenant_id, actor_id, owner_id, allowed_ops | 按平台稳定身份，不按显示名 |
| channel_outbox | logical_reply_id, channel, origin_conversation, state | 回复本源，不镜像全局聊天 |
| approval | id, action_id, payload_hash, task_version, policy_epoch, expires_at, status | 一次性、精确绑定，重启旧请求失效 |
| source_cursor | scope_id, session_id, source_generation, through_seq, state | 原始历史处理水位 |
| memory_job | id, kind, session_id, from_seq, to_seq, baseline_version, status | 固定快照、重试次数与输入hash |
| fact | id, scope_id, owner_type, owner_id, kind, text, status, authority, valid_time, version | active/disputed/superseded/tombstoned |
| fact_version | fact_id, scope_id, version, snapshot_json | 保留每版文本、状态、证据和理由，不能只有hash |
| fact_evidence | fact_id, session_id, seq, source_hash, artifact_ref | 至少有可核查依据或明确 imported 标签 |
| fact_relation | from_fact, to_fact, kind | supports/supersedes/conflicts；禁止支持环 |
| memory_snapshot | scope_id, owner_type, owner_id, version, body, coverage_json | 工作区聚合可检查每个来源版本 |
| fact_consumption | fact_id, fact_version, task_id, action_id, use_kind | 纠错后知道哪些活跃动作受影响 |
| forget_rule | scope_id, source_fingerprint, selector, mode, created_at | 防止同一旧来源重新学回 |
| audit_event | id, scope_id, time, actor, kind, object_id, before_hash, after_hash, reason | 事件型审计，不存完整凭证/推理 |
| runtime_lease | scope_id, holder, fencing_token, expires_at | 多 Host 单写控制；过期不直接恢复业务 |

JSON 列也要应用级 schema 校验；外键 ID 的 scope 在事务中再次检查。source seq 只能在同 Session 和 generation 内比较，不能跨 Session 用数字大小判断哪个决定更晚。

附录 `boop-schema.sql` 给出核心表的可执行 SQLite 设计草案；并非实现了全部 repository、迁移、FTS 与权限代码。

## 07｜命令、读取与事件接口

接口使用 DSH 已鉴权连接/远程服务入口接合，具体注册方法需 G01 验证。禁止监听一个无鉴权的新 localhost 管理端口。下面是 BOOP 逻辑 API，不是既有 DSH RPC。

| API | 输入重点 | 返回／错误 | 是否改变业务 |
|---|---|---|---|
| `GET /boop/bootstrap` | scope | identity/capabilities/coverage | 否 |
| `GET /boop/catalog` | filters/cursor | scoped targets | 否 |
| `GET /boop/tasks` | lifecycle/attention/cursor | stable task projections | 否 |
| `GET /boop/tasks/:id` | id | criteria/actions/evidence | 否 |
| `POST /boop/tasks/propose` | goal/targetRefs | draft or existing candidate | 否 |
| `POST /boop/tasks/:id/accept` | intentRef/expectedVersion | accepted delegation | 是，确立范围 |
| `PATCH /boop/tasks/:id` | expectedVersion/patch/intentRef | newVersion | 是 |
| `POST /boop/actions` | taskId/version/target/payload | actionId/pending/accepted | 是 |
| `POST /boop/tasks/:id/pause` | reason/expectedVersion | paused/cancelOutstanding | 是 |
| `POST /boop/tasks/:id/stop` | actionIds/reason | requested/unsettled list | 是 |
| `POST /boop/tasks/:id/resume` | explicit intentRef/version | eligible or still_blocked | 是 |
| `POST /boop/stop-all` | scope/confirmation | new policyEpoch/unsettled | 是，不经 LLM |
| `POST /boop/approvals/:id/decide` | decision/nonce/hash | allowed/rejected/stale | 仅人类鉴权通道 |
| `POST /boop/workspace-changes/preview` | operation/targetRefs | exact diff/risk | 否 |
| `POST /boop/workspace-changes/commit` | previewHash/approval/version | item outcomes | 是 |
| `GET /boop/memory/context` | objectRef/question | snapshot/coverage/evidence | 否 |
| `POST /boop/memory/initialize` | fresh/history/import | batchId | 仅 BOOP 数据 |
| `POST /boop/memory/import/preview` | bounded text or safe blob | candidates/warnings | 否 |
| `POST /boop/memory/correct` | candidate/evidenceRef | correctionId | 候选 |
| `POST /boop/memory/forget` | selector/mode/confirm | effects/cacheInvalidation | 记忆变更 |
| `POST /boop/channels/bind` | short-lived proof | verified binding | 安全设置 |
| `POST /boop/data/export` | selection | scoped export receipt | 数据外发需确认 |
| `GET /boop/events` | cursor | typed projections | 否 |

客户端不得提交 owner_id/principal/granted=true 作为权限依据。所有命令都有 operationId；有目标版本的命令都带 expectedVersion。重复请求返回同一操作的当前结果，不执行第二次。分页采用稳定 cursor，错误不返回混合真假列表。

统一错误：`CAPABILITY_UNAVAILABLE`、`VERSION_UNSUPPORTED`、`SCOPE_DENIED`、`TARGET_AMBIGUOUS`、`TASK_VERSION_CONFLICT`、`APPROVAL_REQUIRED`、`APPROVAL_STALE`、`RECOVERY_REQUIRED`、`OUTCOME_UNKNOWN`、`MEMORY_STALE`、`WRITER_HELD`、`MODEL_UNAVAILABLE`、`RATE_LIMITED`。错误响应含可安全展示的说明和 retryable，不泄露路径密钥或原始请求头。

## 08｜可靠派发与人工优先

### 派发过程

A. 读取 Task 当前 version/policyEpoch 与目标最新用户控制水位；检查 active、范围、资源锁、来源可信度。  
B. 生成 actionId/messageId，规范化 payload 并哈希；将 action 与 outbox 在一个事务中落库。  
C. 如需审批，进入 awaiting_approval；审批通过后重新读取版本和权限，而非直接执行旧 closure。  
D. 目标 Session gate 通过后，解析 Agent，构造 `boop-command` 来源消息，默认 next-turn queue；只有用户明确调整/紧急风险才 steer。  
E. 记录 native queue/admission 证据并 flush；outbox accepted 只表示已接收。  
F. 用 actionId/messageId/turnId 关联原执行；结束后产生验收候选，不直接完成任务。

每个自定义 source 包含 scopeId/taskId/actionId/initiatorRef，真实身份来自已鉴权 adapter，不能让 LLM 自由伪造。原生人类输入也不只看 role=user；需按 rc.2 真实 source 类型及入站关联识别。代理消息和工具注入不得算作新的用户授权。[S04][S08]

### 人工介入与竞态

同一任务命令串行化；用户输入一旦被观察到，即推进 controlEpoch，撤销旧待发动作。普通细节按最新指令更新；含糊讨论仅标记需判断，不自动重排所有任务。派发前检查与 native enqueue 不是跨系统原子事务，必须在目标 `pre-step` 再做一次 BOOP 自有 provenance gate。用户修改发生在不可逆工具已经执行之后，只能说明现场，不宣称撤回成功。

同目录或其他同一可变资源默认不并行派写；资源键优先 canonical cwd/repo/worktree，无法确认则保守同域串行。对不归 BOOP 的运行只观察，不停它；暂停 BOOP 自己的冲突动作。

## 09｜故障窗口与恢复策略

| 故障点 | 恢复动作 | 禁止行为 |
|---|---|---|
| intent 落库前失败 | 无动作，原请求可重提 | 伪造已派发 |
| intent 已落库、尚未发送 | 重启标记 recovery_required | 自动投递业务 |
| 发送后未拿到接收证据 | 查 native inbox/log 对账 | 换新 ID 重发 |
| 已接收但 BOOP DB 未标记 | 依据同 messageId/source 补记 | 重复创建 Task |
| 工具写入后结果丢失 | outcome_unknown，核实外部实际状态 | 假定失败后重做 |
| 记忆提取成功、事务失败 | 重跑同固定范围，版本 CAS | 先推进 cursor 再写事实 |
| 工作区聚合 CAS 冲突 | 丢弃旧候选，用新依赖快照重聚合 | 最后写入者覆盖 |
| lease 丢失 | 停止新派发，旧者持有的 fencingToken 无效 | 旧 Host 继续驱动 |

**谨慎恢复必须管到原生 inbox，而不是只暂停 BOOP 定时器。** Host 启动早期 gate 阻断旧 `boop-command` 待执行消息及旧受管 continuation。需要确认其属于本次恢复授权后才放行；原 Session 中用户自己发出的非 BOOP 任务不由插件擅自禁用。若启动顺序无法可靠满足，G04 判失败，v1 写模式不可上线。

## 10｜审批设计与信任边界

第一道门是 Task delegation：允许对象、动作类型、阶段、资源范围和有效控制 epoch。第二道门是原 Session 工具执行审批。BOOP 只能请求和转达，不能拥有审批决定工具。

审批记录绑定 `actionId + targetIdentity + normalizedPayloadHash + taskVersion + policyEpoch + requestingOwner + expiresAt + nonce`。修改参数、目标目录、任务范围、身份或重启都会令旧审批失效。一次性消费用事务 CAS，重复回调返回已处理而非再次放行。

rc.2 原生审批可用时复用其请求与 UI；自定义管理动作审批走 BOOP 自己的人类确认接口。不得混成一个永久 Full Access 按钮。目标高权限 preset 不能自动抬高 BOOP 的管理范围；受托执行中的工具若超出授权，BOOP provenance gate 还应收紧。此 gate 能限制合作式 DSH 工具链，不构成对恶意同进程插件/任意系统代码的完整沙箱。

默认等级：目录/状态读 R0；受托范围内、可追溯的有限改写 R1；外发、批量改动、推送、资源配置 R2；部署、删除数据、凭证/权限操作 R3。R2/R3 每次精确审批；R3 仅 Web/Desktop。政策升级只能由用户设置确认，不能由 learned memory 更新。

## 11｜源头工作记忆的详细算法

1. 订阅原生事件，记录 dirty 不直接跑模型；记录 endingReason，排除 BOOP 内部 maintenance 来源防止递归。
2. 把若干短轮变化合并为固定 job。读取 `processedCursor+1..durableToSeq`，不假定内存 turn/end 已落盘。
3. 原始事件去掉秘密字段与无关大结果；保留证据指针与哈希，不只拿最后一条 assistant 回复。
4. 切片按 Turn 与关键事件边界；带少量前文理解指代，超长单消息切块并保留覆盖范围，不能静默截去关键结尾。
5. 模型生成 MemoryProposal；程序检查 source 范围、target、schema、长度、敏感内容和候选 authority。
6. 一个事务内写 fact/version/evidence/cursor/job-done/workspace-dirty。一个 Session 同时只有一个有效提交者。
7. Workspace 聚合依据多个 Session 的明确 facts 和 task references，不拼接摘要；每条结论有 supportFactIds 和输入版本向量。
8. 更新全文索引；发布 memoryChanged 事件，不直接唤醒所有 Agent。
9. 通过 fact_consumption 标记受影响 active Task/Action，撤销尚未执行的过时建议；已完成任务只在实质风险下重查。

**仅有 Agent 自述**记录为 `agent_reported`。**工具返回**记录为 `tool_observed`，仍不自动成为全项目验收通过。**用户明确决定**可以成为 `user_confirmed`，但它的有效范围和时效仍需标明。冲突事实同时保留，避免 last-write-wins。

### 多轮/多 Session 场景

- Fork：记录 inherited prefix 的 lineage，不把继承证据再算一次独立交付；child 后续新事实不覆盖 parent 的范围。
- 改名：ID 不变，展示名更新；路径变动：重新核实对象归属，禁止只凭路径文本合并。
- 原始记录丢失：证据引用显示 unavailable，保留来源元数据；不能继续声称已回查。
- 项目未委托：可以更新批准范围内的记忆，不产生 Task delegation。
- 摘要未更新：查询可显示 stale；实际动作前原始新增用户决策必须核查。

## 12｜初始化与导入的事务边界

`fresh`：登记目录与起始水位；不创建历史学习 job。  
`history`：持久化清单 snapshot，按活跃顺序入队；支持暂停/续跑/排除；新增记录另外排队，避免移动边界造成遗漏。  
`import`：默认 UTF-8 文本单文件≤5MiB（设计初值），JSON 版本/大小/字段白名单；禁止包含可执行扩展、自动读取路径、模板指令直接生效。导入后是 unverified 候选，不复制审批、策略、活动任务和渠道绑定。

初始化进度由清单对象数、已处理记录和失败项构成，不称“学习准确率”。导入和历史学习都只改变 BOOP 记忆，不恢复旧任务或创建新执行代理。

## 13｜遗忘、纠错与派生数据失效

纠错：保存 evidence → 新事实版本 → supersedes 旧事实 → 废弃受影响聚合快照 → 更新检索索引 → 标记使用旧事实的活跃动作待核查。已放进目标 Session 上下文的旧信息不能物理“抹除”；在有效委托内发出明确纠正或暂停，并核查已发生影响。

遗忘：事务内 tombstone + forget_rule，然后失效全文/向量索引、上下文缓存、候选 job 和聚合。不得只删 Markdown。用户提供新明确证据时可以通过显式操作解除对应排除，不让旧历史扫描自行复活。

原始 DSH 日志默认保留，除非用户另外做原生删除；UI 必须说明“忘记”与“删除原聊天”不同。备份不能保证安全物理擦除，敏感信息处理需列明在线副本、导出、备份保留策略；不承诺 SQLite 删除后磁盘不可恢复。

## 14｜RAG 查询计划

| 查询类型 | 路径 |
|---|---|
| 精确 Task／审批列表 | SQL 结构化读取，不做相似搜索 |
| 指定 Workspace 状态 | 最新 memory_snapshot + task 当前状态 |
| 历史决定 | scope 过滤 → FTS → 精确 source 回读 |
| 模糊项目描述 | 名称/别名 → FTS → 可选语义补充 → 对象确认 |
| 是否已授权 | approval/intent 实体查询，禁止语义推断 |

QueryPlanner 在每个结果上返回 freshness、coverage、evidence 和冲突标记。mandatory constraints 不参与 Top-K 竞争。重排不得跨 scope，向量结果也必须经过同样 ACL、active/tombstone/版本过滤。embedding 服务缺失不影响核心精确路径。[S11][S17][S26]

## 15｜双向钉钉／飞书适配器

适配器契约：`connect / verifyEnvelope / normalizeMessage / acknowledgeReceipt / sendReply / disconnect`。渠道网络 ACK 只表示收件，不等待长模型推理；验证后先写 ingress，再异步投递主会话。平台重投命中 `(channel, app, tenant, eventId)` 唯一键，不重复委托。

钉钉优先应用机器人 Stream，避免为了收消息公开暴露本地服务；飞书使用官方 SDK 的事件接收能力，长连接是否适合当前应用类型与 SDK 版本在 G07 核验。不能把自定义群机器人发送 Webhook 当成双向聊天机器人。应用权限、身份ID类型、ACK时限、主动回复时限与重连语义按官方协议锁定。[S24][S25]

绑定：在本地受信设置页生成短期一次码 → 本人向对应应用单聊发送 → 展示平台租户与稳定用户ID供本地确认 → 存 allowedOps。用户名、昵称、手机号文本不是绑定凭据。默认拒绝群聊、未知人、转发的第三方命令以及正文伪造 JSON 权限。

`InboundEnvelope` 保留 channel/tenant/app/actor/conversation/message/event/timestamp/verifiedBinding。原消息和 DSH 主聊天的 durable messageId 双向关联。跨渠道回复遵守来源可见性；不将主聊天的其他项目信息广播到 IM。

第一版支持文本与明确任务引用。文件、语音、复杂卡片单独声明能力，不自动抓外部附件 URL。危险审批默认返回任务编号与“请在 DSH 中确认”，不给包含 token 的本地链接。普通“同意”若没有唯一待决低风险目标，不执行。

离线期间消息是否重投由平台决定；Host 恢复后过期委托转待确认，不自动补跑危险动作。停止 BOOP 时关闭渠道接收，不能留下独立无限运行机器人。

## 16｜自动化与业务巡检

原生 Schedule 可选，通过 adapter 管理委托关联。定时消息不是永久权限：进入 BOOP 控制器再次判断 Task/lifecycle/policyEpoch。为了实施谨慎恢复，不把不可控的旧业务命令直接挂在原 Session 定时器上自动补跑。

默认巡检是事件驱动加轻量补偿扫描：受托 active 任务定期读状态投影，未受托项目只登记变化；模型仅在状态需要解释、验收或记忆整理时调用。设计补偿间隔 60s（可调），不表示每分钟全量LLM检查。使用单调计时处理进程内超时，UTC保存时间，展示与定时规则保存 IANA 时区。漏过多个历史周期默认合并一条待检查，不突发补发N次。

## 17｜前端数据流与性能边界

前端从 bootstrap 得 capabilities 与当前scope，任务读 API，事件流推 projection version。每个事件带 object/version，旧版本不覆盖新值；重连先 baseline，再增量。Web 断连显示 stale，不能继续显示 live running。

只在 BOOP 主 Session 贡献身份/任务快捷入口；看板注册独立 main key。点击任务原 Session 引用走原生导航，保留 BOOP draft/scroll/contextRef；不在同一 Session 同时挂两个可编辑 composer。[S05][S06]

首版支持 100 Workspace、2,000 Session 元数据、50 活跃委托、后台增量队列上限 10,000（设计压力基线，非实测承诺）。超量分页、合并 dirty；不能丢弃未处理记录水位。历史正文不全载入内存；FTS与大批事务放受控执行路径，避免阻塞渲染和Host主循环。

## 18｜运行观测与隐私

不做费用页。保留必要诊断：模型路由、推理排队时长、请求Token（若服务报告）、后台job积压、memory lag、未知动作数、过期审批、channel重投数、lease状态。默认不记录完整 system prompt、原始工具秘密和推理正文。

调试导出先脱敏预览，包含版本、错误码、对象匿名ID和结构，不默认打包全部会话。所有日志按 scope 隔离；诊断期限初值7天可调，任务与记忆按用户数据策略保留。日志轮转不能删除未结算审计关系。

## 19｜备份、迁移、停用与卸载

数据库备份使用一致性 snapshot/backup API，不直接复制有活跃 WAL 的单一文件。升级检查 schema 兼容区间；任何破坏式迁移前创建可恢复备份并进行 FK/integrity 检查。只支持测试过的降级路径，不把旧插件直接打开新 schema。

停用：关闭新派发、撤销待审批动作、停止自有调度、列出当前受托运行；普通用户原 Session 不自动删除。卸载前展示三类数据：BOOP 自有数据库、DSH 主聊天/任务 Session、用户项目文件。默认只停能力和保留数据，清理 BOOP 数据需再次确认，不删除项目文件。未确认结束的外部进程列为“仍需核查”。

## 20｜来源与许可策略

DSH 为执行底座，BOT 参考身份/通信/记忆纪律，MUSE 参考活动/目标/渠道任务关联。初始实施以自研 BOOP 领域模块为主；“借鉴”不代表已批准复制全部代码。[S07][S08][S09][S15][S16]

BOT 包声明 Apache-2.0，MUSE 包声明 GPL-3.0-or-later。拟公开 BOOP 的许可在实际引用清单审查后决定；不能仅因“只复制了一个函数”就忽略衍生义务，也不能未经分析宣布整个 DSH 必须换许可。建议从第一天维护 SPDX、NOTICE、来源文件/提交、修改记录与依赖锁；MUSE 先学习机制，直接源码导入需专门审查。[S21][S22]
