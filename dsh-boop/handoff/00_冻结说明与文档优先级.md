# 冻结说明与文档优先级

> 交付编号：v1.2-FROZEN-R1 · 日期：2026-10-17  
> 用户确认：“很棒就按照这稿钉住，给我一个完整的文档包，准备给开发团队进入开发”。

## 1. 冻结什么

产品基线固定为前一轮完整的 v1.2，包括五册主方案、Taskboard 复用附册、接口与数据设计附件、已确认 KV／实体图和工程 Token。`baseline/` 保留该 ZIP 的全部 65 个原始文件，逐文件字节不变。文件指纹见 `manifests/FROZEN_BASELINE.json`。

交接版本号只表示新增开工材料；**不将设计悄悄升级为 v1.3，也不修改模型、权限、记忆架构或角色外形。** 工程任务是现有范围的展开，不是新增功能授权。

## 2. 三种状态必须分开

| 对象 | 状态 | 意义 |
|---|---|---|
| 产品、架构、交互与视觉方向 | 用户确认／冻结 | 团队按此实现；改变需走变更流程 |
| 设计参数、示例接口和数据 schema | 已接受的实现起点，仍需编译／探测／回归 | 可在不破坏约束的前提下实现；可调参数要记录理由与证据 |
| 插件、模型、渠道、兼容性 | 未运行验收 | 不得因为文档冻结将任何 Gate 改为 PASS |

原册页眉可能保留 v1.0/v1.1、“可评审”“建议”等历史描述。它们标示该文件形成时的状态，不表示本次需要重开所有产品讨论；其明确写出的运行验证前提仍然有效。

## 4. 冻结后的不可降级约束

不重写原生 Loop；不修改普通 Session 默认模型、人格和搜索配置；不冒充人类发送代理消息；不把 accepted 或 turn/end 当验收完成；不复制第二套任务权威；不让记忆授予权限；不把未知外部结果自动重试；不在 Host 重启后偷偷恢复业务；不把用户数据发给未经允许的模型或渠道。

主聊天 Stop、任务暂停、任务停止、全停的范围必须保持区别。高风险审批不得由模型代答。不同 DSH_HOME 默认隔离，同数据域多 Host 不同时获得写控制。

## 5. 允许工程自行细化的部分

模块内函数和文件组织、单元测试实现、构建脚本、诊断字段、数值初值的压测调整，可以在对应 Issue/PR 中评审记录，不必要求用户逐个选择。调整不得扩大数据出域、执行权、默认自治范围或取消既定功能。

如果 rc.2 接口无法满足关键约束，保持对应能力关闭，提交最小复现、影响范围和替代建议；不能自行升级 DSH、绕过审批、修改原生日志或使用 CDP/无鉴权 Shell 作为捷径。

## 6. 变更方式

保留 `baseline/` 不变。所有产品／安全／数据归属／视觉方向变更填写 `templates/CHANGE_REQUEST.md`，经产品负责人和技术审查批准后，在下一版本更新正文、接口、验收和 manifest。技术验证失败不是默认改方案的许可。

## 7. 素材与公开发布

这是内部开发交接包，不等于可原样公开的发布包。`baseline/references/`、历史 QA 截图，以及内嵌 Cellgent 参考图的阅读器，在开源前需做资产公开范围检查。产品代码只带确认允许分发的资源；不得把凭证、真实对话或本地路径补进本包后公开。

校验清单用于识别内容变化，不是数字签名，也不单独证明来源真实性。ZIP 校验值由交付时单独提供。
