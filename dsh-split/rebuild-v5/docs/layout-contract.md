# DSH Split v5 布局与手势契约

本文件只以 `reference/dsh-split-v5-frozen-20261015/` 中的 `dsh-split-final-plan.html`、`dsh-split-interactive-demo.html` 和 `engineering-tasks.md` 为产品规格。未读取、借用或继承旧插件实现。交互原型是离线演示，不是原生 DSH 集成证据；其中模拟消息、文件、终端与演示存档不进入新插件。

依据标记：**P** 为最终方案 HTML 行号，**D** 为交互原型 HTML 行号，**W** 为工程任务编号。规格冲突时以最终方案的生产职责边界及工程任务为准；原型用于冻结视觉初值、命中区和操作手感。

## 1. 布局所有权

- 一个 WorkbenchHost、一份外层 Dockview。一个 Panel 对应一个会话，一个 Group 只能容纳一个 Panel。隐藏 IDE 标签栏；中心合并、标签合并、浮动、popout、跨工作区拖入均不属于本期。（P150–154，W005）
- Dockview 是外层几何的唯一事实来源；普通移动、缩放通过其公开 API 执行，不能维护第二份可写外层树或用 `fromJSON` 重建页面。`fromJSON` 限初始恢复、明确重置和错误恢复。（P151–154）
- SessionSurface 内保持正文、分隔条、Sidebar 三个稳定子节点，以 CSS Grid 改行列及区域。换边不改 iframe 的父节点，不重挂业务子树。（P155–158，W017）
- Sidebar 永远属于 Session；整会话移动时一起移动。每个会话只拥有一块原生 Sidebar。Sidebar Tab、导航、资源身份与关闭流程仍由原生系统拥有。（P73、175–192）
- Panel 身份和 Session 身份不同。移动/缩放保持二者；显式切换会话保留 Panel 位置但递增 bindingEpoch。一个 Session 同时只能有一个合法可编辑根，包括隐藏的原生页面。（P211–226、272–280）

`535px` 比左右最低合计 `220 + 12 + 290 = 522px` 更保守；新实现保留该冻结阈值，不自行缩减。所有尺寸以 CSS 像素计；比例分母是去除 `12px` 接缝后的有效空间。

Sidebar 保留 `1px` 细边框和静态阴影。浅色：`0 1px 2px rgba(24,28,21,.035), 0 4px 12px -4px rgba(24,28,21,.065)`；深色：`0 1px 2px rgba(0,0,0,.12), 0 4px 12px -4px rgba(0,0,0,.20)`。阴影不随焦点变化、不应用于会话外壳、不参与尺寸。（P75，D8–9、13）

非当前会话用独立伪元素浅灰罩：浅色 `rgba(140,148,157,.075)`、深色 `rgba(162,170,180,.045)`，`pointer-events:none`。禁止对整根节点设置 opacity、filter 或 inert。首次点击直接激活并完成原操作。系统失焦仍保留最后明确活动会话，不能全部蒙灰。全局菜单/审批/灯箱走原生 portal，不被遮罩和圆角裁掉。（P75、134，W020）

## 3. 会话菜单、普通导航与异步目标

1. 唯一增屏入口是原生左侧具体会话的菜单，新增项名称为“向右分屏”“向下分屏”，保留该菜单原有项。会话标题不放分屏入口。（P76，W011）
2. 当前 A 活跃时打开 B 菜单，只捕获 `{anchorPanelId, anchorBindingEpoch, targetSessionId, direction}`，既不导航 B，也不改变活动 A。（P76，W011–W012）
3. 点击分屏直接把 B 放到捕获 A 的右/下方，不再选择第二次会话，不擅自换方向。（P76）
4. B 已显示时只提供定位；右/下分屏禁用且说明不重复创建。普通点击已显示 B 仅定位；普通点击未显示 B 在活动 Panel 内切换。（P76，W011–W012）
5. 无当前参照、目标失效、空间不足、临时放大、窄屏投影均拒绝增屏并给出具体原因。失败不能留下空 Group 或永久空窗格。（P76，D156，W022）
6. 菜单关闭/Esc 必须保持布局和活动会话，Esc 后焦点返回触发按钮。（P76，D160、177）
7. 异步准备引用完成时重新校验来源 Panel、bindingEpoch、目标唯一性及操作时效。来源已关闭/换绑、目标删除或更新意图到来则拒绝旧动作；不可回退全局 current，也不删除已合法创建的 Session。（P278–279，W012）

## 4. 外层整会话移动与尺寸调整

- 只有会话标题空白/把手可启动外层拖动；按钮、菜单、正文选区、Composer、Sidebar 标题、原生 Tab 不启动它。标题方向菜单提供键盘/触摸等效路径。（P77–84，W015）
- 按下仅记录起点；超过阈值后保留原内容原位，显示轻量标签和落点预览。移动指针只更新预览，松手一次公开移动提交。（P79–82）
- 预览先计算移除来源后的最终目标范围。例如 A 左 B 右，把 A 拖到 B 下方应得到 B 上 A 下，不能预览不存在的第三块空位。（P81、86，W015）
- 只能落到其他可见会话的四边。中央、目录、源会话、应用外、空间不足无效；无效松手保持原布局。移动不交换 SessionId，不通过 remove+add 伪造。（P83、86，D153–154、173）
- 单会话、临时放大、窄屏投影时外层移动不可用。（D155–166）
- 透明外层 resize 命中区保持方向光标、separator 语义和键盘尺寸反馈。每帧最多更新一次几何，尺寸实时跟手，无宽高长动画。（P134、315–316，W016）
- 双击在最小尺寸约束内均分。外层键盘原型步长为有效空间比例 `.025`；原型储存数值范围 `.08–.92`。生产最终尺寸以引擎约束为准，不绘制焦点分割线。（D146，W016）
- 调整开始保存原比例；Esc/cancel 恢复原比例；只在成功提交时存档。（D167、171、175，W016）

## 5. Sidebar 四边、比例与手势

- 拖 Sidebar 标题只在**所属会话正文区域**显示四边目标；其他会话、应用外无目标。原方向视为无变化。松手仅提交一次方向。（P87–104，D168、173，W017）
- 点击标题或 Enter/Space 打开四方向菜单；与拖动调用相同换边操作。Esc 关闭后返回标题。完成拖动后的 click 不得误开菜单。（P88，D112、158、160、174，W018）
- 标题右上角没有额外停靠/关闭两个 icon；收起/展开使用会话标题原有 Sidebar 按钮。原生 Tab 内部按钮及其关闭能力继续保留。（P75、88–89，W018）
- 换边只改 side，显式换边展开 Sidebar；从左右到上下使用先前 verticalRatio，回到左右恢复 horizontalRatio。新会话默认右、`.36/.40`。（P100、112、132，D85、161）
- resize 只更新当前轴：左右改横比例，上下改纵比例；左/上跟随正指针增量，右/下使用反向增量。分别以 `220/290`、`140/170` 最小尺寸钳制。不能拖窄自动收起。（P119–132，D171）
- 双击当前轴设 `.5` 后按最小尺寸钳制，另一轴保留。键盘原型步长 `.03`，方向随实际边的指针方向；原型保守比例区间 `.18–.8` 不取代真实尺寸下限。（D117）
- 拖内部 Tab 属于原生 Tab 层，不搬 Sidebar；拖 Sidebar 不搬会话。首版不拆出单 Tab、不跨会话迁移、不新增全局 Sidebar。（P89，W017、W021）
- 换边/调整大小不重新打开 URL、Terminal、不替换 Tab、不移动 iframe 父节点；业务状态和资源保活由原生 provider 负责。（P100、132–133、275、282–283，W017、W026）

## 6. 隐藏、关闭、放大与窄屏

| 动作 | 几何变化 | 资源语义 |
| --- | --- | --- |
| 收起 Sidebar | 正文占满本会话，方向及两轴比例保留 | 不清 Tab，不停止终端 |
| 展开 Sidebar | 恢复上次方向和比例 | 使用原生现有 Tab/资源 |
| 移动会话/Sidebar | 位置变化 | 不关闭再创建资源 |
| 临时放大 | 只显示目标；底层桌面几何不变 | 其余视图隐藏，不停止任务 |
| 恢复放大 | 返回此前几何比例 | 仍存活内容身份不变 |
| 关闭会话视图 | 引擎移除呈现位置，活动者确定性转移 | 不删除 Session；释放视图引用仍遵守原生持有规则 |

关闭会话视图有两个等价入口：原生左侧会话菜单的"关闭此分屏"，以及该 pane 会话列 Header 行最右侧、原生 ▯（Sidebar 控件）右边的插件自绘控件（`[data-dsh-split-close]`，见 `docs/visual-contract.md` 记录的 Header 内边距边界例外）。两者都只在 `canClose`（该会话是分屏之一，且 pane 数 > 1）成立时出现：单个 pane 就是普通视图，不提供关闭；否则会留下永久空工作台。插件不占用原生 `header.corner`（属 Sidebar 控件），也不新增第二条会话标题栏。
| 显式关闭/替换终端 Tab | 原生 Tab 行为 | 必须沿原生 close/清理/重试流程 |
| 外层窄屏投影 | 仅显示明确活动会话 | 其他会话资源继续由原生拥有 |
| 内层空间不足 | 本会话区域单页 Sidebar，保留返回对话 | 不全屏覆盖工作台、不毁资源 |

依据：P107–133、158、273–283、298–299；D138–146、151–152；W013、W022、W026。

宽屏恢复必须回到桌面原排列、方向与比例。窄屏投影不能写回桌面快照。最大化是临时状态，重载默认不恢复。关闭到零用原生新建/选择入口，不为分屏产生永久空 Panel。（P200–207、298–299，W013、W022）

## 7. 取消和焦点优先级

- 有效布局手势优先消费 Escape，停止传播，恢复操作前状态；不得意外触发原生双 Esc 停止 Agent。（P84，D177，W021）
- Escape、pointercancel、lostpointercapture、窗口失焦、卸载均需结束手势并释放 pointer capture、iframe 屏障、临时预览、光标及全局监听。（P84、283、331–332，W021）
- iframe 屏障仅有效手势期间存在且必须实际接收指针；`pointer-events:none` 不能充当事件盾。原始内容始终留在稳定父节点内。（P282–283）
- 会话标题、Sidebar 标题及控件为 `-webkit-app-region:no-drag`；系统标题区域仍按原生行为。（D9、12，P284，W021）
- IME、重复按键、原生菜单/审批和原生快捷键尊重原生裁决。移动只激活容器，不强行 focus Composer。（P134，W020–W021）
- iframe 焦点必须验证事件来源与已拥有的 frame/host 绑定；只凭消息自报 SessionId 不能激活会话。（P134，W034）

## 8. 几何存档与恢复边界

生产快照只含：schemaVersion、宿主基线、固定引擎版本、安全 Panel/Session 引用、Dockview 几何快照、逐 Session Sidebar 方向及两轴比例，以及必要的显隐呈现状态。消息、草稿、模型、运行状态、Tab URL、终端身份、provider 数据、凭证、连接数据不复制。（P159–207、285–293，W027）

存储命名空间由已认证宿主提供 connection/profile scope；客户端 key 不构成授权。验证体积、递归深度、重复 Panel/Session、未知类型、非法数字和引擎不变量。成功几何提交防抖保存；流式输出、每帧 resize、临时焦点和窄屏投影不触发全量存档。存储失败保留内存工作态并提示。（P287–292、323–324，W027、W034）

恢复顺序：宿主身份/provider 就绪 → 校验版本和形状 → 准备并授权 Session 引用 → 唯一性校验 → 采用原生 Sidebar 已存状态 → 一次恢复外层 → 报告实际可见范围。恢复不发送消息、不启动 Agent、不新建替代终端。失权内容不能泄漏标题；provider 延迟不能直接清空快照。（P290–293，W028）

旧 `dsh.split.v1` 仅允许迁移已验证且去重的 Session 引用；本次禁止读取历史插件代码，所以无法凭空推断旧格式。未知格式拒绝/保留原档，新旧 key 分开；不删除 `dsh.sidebar-right.v1.<sessionId>` 等原生存档。（P294–299，W028）

## 9. 本模块的验证边界

`src/geometry.ts` 的纯测试验证数值边界、四边坐标、两轴独立、菜单捕获、目标过期、结构校验及序列化白名单。它不证明实际 Dockview 的容器身份、React/Lexical 唯一编辑根、iframe 不重载、原生终端保活、菜单/portal 接入、键盘事件裁决或宿主热启停。上述必须在固定 DSH rc.2 与真实 provider 中验证（W003–W007、W026、W031–W034）。

本次另外使用已安装的 Dockview Core **8.5.1** 与 JSDOM 做实际引擎集成测试，核对取消调尺寸、外层移动、单组单窗、重复定位、窄屏/放大恢复和 mount 父节点身份。测试的 `getBoundingClientRect` 根据内联尺寸显式模拟，因此只能证明引擎调用、对象身份和状态不变量，不能代替浏览器 CSS、iframe 页面加载次数或真实原生编辑器的验收。

实现取舍依据锁定版本公开包：`node_modules/dockview-core/dist/package/main.esm.mjs` 的 Splitview `layout` / `relayout`（1575–1607）、Gridview `serialize`（2446–2480）及 `removeView`（2715–2764）、Dockview `_doMoveGroup`（18548–18675）。普通取消与窄屏还原不调用 `fromJSON`：外 resize 用原生 sash 回到开始坐标后取消；退出窄屏/放大前先把仍处于放大态的引擎布局到保存的桌面尺寸，再退出放大，最后适配当前尺寸。`fromJSON` 只用于经过校验的初次恢复，不能把 `reuseExistingPanels` 当作 DOM 父节点绝不变化的证明。

`movePreviewRect` 是只读矩形查询，不生成或存储候选布局树。目前可验证的框覆盖两窗跨轴分割、两窗同轴重排和单子根包装；两窗左右换上下会先释放源位置，因此预览跨整个工作区。三个以上 Panel、嵌套分支、有限最大约束或需要向其他区域借空间时返回 `null`，仅显示方向标签。`null` 不等于禁止提交，提交仍由 `minimumAfterMove` 校验并交给实际 Dockview 执行；不能用旧目标框的一半作为回退预览。

Dockview 会在约束计算后从内部份额扣除主题 gap，因此传入引擎的最小约束为 `342 × 282px`，保留完整 `12px` 余量，保证实际内容至少 `330 × 270px`。当前空间预检使用该内部约束再计入 gap，属于保守判定；窄屏投影或分屏禁用可能比理论视觉下限略早触发。

快照的 256 KiB、64 Panel、256 节点、16 层及 256 字符 ID 上限是本次实现的校验保护，并非原型额外产品限制。新命名空间为 `dsh.split.v5.geometry:<encoded scope>`，本次不读取或迁入旧插件快照。
