# Chromium 交互验收

2026-10-16，在本机 `http://127.0.0.1:4417/tests/fixture.html` 使用实际 Chromium 页面操作验证。页面加载生产 Workbench/SessionPane/手势/样式，但会话、终端和 iframe 内容是明确标注的测试替身。

已操作并观察到：

1. 原型规格的会话标题与 Sidebar 标题、圆角、静态阴影、透明外分隔；深色主题可切换，原生区域内标签样式没有被外层 Dockview 重置覆盖。
2. Sidebar 点击菜单选择下方，再实际拖动标题到左侧。聊天草稿“重构验收：移动 Sidebar 后保留这段草稿”和 iframe 输入保持，iframe 加载次数仍为 1。
3. 打开 B 的菜单时当前 A 不切换，选择向右分屏后 A、B 各有自己的内容。窄会话内 Sidebar 投影有“返回会话”入口。
4. 点击 A 的标题打开移动对话框，把 A 放到 B 下方；两会话铺满相应区域，未产生空分屏，iframe 未重载，草稿保留。
5. 外层分隔用 ArrowDown 从 50/50 调整到约 53/47；将浏览器视口设为 700×720，只投影当前会话；切换 B、A 后恢复默认 1280×720，实际两窗高度恢复为 330/298，原草稿仍在。测试后已取消临时视口覆盖。
6. 非活动 B 的终端 Tab 首次点击即生效，并成为活动会话。隐藏再显示 Sidebar，测试终端身份仍为 terminal-B-8，运行计数继续增长。
7. 刷新页面后外层上下布局及 Sidebar 的停靠方向恢复。模拟草稿不持久化是夹具约定，生产草稿仍由 DSH 原生负责。

后续的最小可见尺寸余量、复杂预览保守退化、原生 fullscreen 退出与接入补丁以最终自动测试为准。此记录不声称已经对重启后的真实 DSH 桌面执行全流程验收。
