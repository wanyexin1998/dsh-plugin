# 个人与企业机器人安装

同一个插件包支持个人本机托管和企业预配置。个人 DWS 数据授权仍使用原有流程；不需要机器人时，只完成个人授权即可。

## 个人本机

安装后进入钉钉连接，完成个人授权，再点击个人机器人的配置按钮。填写有管理权限的企业内部应用 Client ID 和 Client Secret。应用需要启用 Stream 机器人并发布到自己的可见范围。

在应用安全设置的重定向 URL 中登记页面显示的回调地址，然后点击连接并确认身份。回调不是消息接收 Webhook，机器人保持 Stream 模式。

个人服务仅监听本机，固定使用 19878 端口。端口冲突不会自动更换。托管 DSH 退出或电脑休眠时服务不可用。配置好的个人服务随 DSH 启动恢复；停止托管会取消自动托管，但保留应用凭据以便重新配置。

个人向导默认只接收私聊；需要群准入配置时使用服务器网关的 `allowedGroups`。

同一机器人不要在多台电脑启动独立网关；多机使用应选择企业服务器部署。同一系统用户的多个 DSH 实例会通过本地锁阻止重复托管。

## 企业服务器

沿用 `dsh-dingtalk gateway --config <私有配置文件>`，配置格式见 PHASE3.md。由服务器现有服务管理工具负责自启与异常恢复。将 HTTPS/WSS 入口转发到网关，保留 WebSocket Upgrade，并登记 `https://服务地址/relay/callback`。

服务器的应用凭据和绑定目录须持久化，置于插件安装目录之外。员工电脑不分发 Client Secret。管理员将以下字段合入员工实际 DSH Profile 的 `dingtalk-channel` 配置，不覆盖其他插件配置：

```yaml
robotConnection:
  mode: enterprise
  corpId: YOUR_CORP_ID
  clientId: YOUR_ROBOT_CLIENT_ID
  displayName: 企业工作助手
  gatewayUrl: wss://gateway.example.com/relay
```

员工完成个人 DWS 授权后，只需点击企业机器人的连接按钮并在钉钉页面确认身份。企业模式不会启动本机网关，也不要求员工输入地址或机器人凭据。

企业配置有误或服务器离线不会回退个人模式。改变目标配置需要重新配对。企业预配置与已启用个人托管冲突时，应先停用个人托管再部署企业配置。

## 升级与诊断

旧 `relay: true` 及其原有绑定继续走兼容路径，不将用户级旧设备凭据复制到新的 Profile。新模式设备状态按 Profile 隔离，网关状态按机器人隔离。个人凭据复用 DSH 凭据文件，UI 不回显 Secret。

使用 `doctor --profile <实际 Profile> --json` 查看当前入口；未发生真实卡片调用时，卡片能力应保持未验证。HTTP 页面与 Desktop 自定义 Origin 都必须实际验证按钮和浏览器返回。

发布前验收：个人安装/回调/授权/重启；企业预配置/两个用户独立路由/服务器重启；取消、身份不一致、新设备替换、端口占用、多 Profile；Thinking、实时卡片和 Done。自动化模拟不能替代真实钉钉权限和 Desktop 壳验收。

## 本次验证范围

开发版本 `0.2.0-dev.12` 已在当前 Windows 开发机完成个人模式真实配对；用户确认查询当前账号身份正确，Thinking、流式卡片和完成状态可用。测试实例重启后无需重新扫码，后台连接已自动恢复，用户再次确认私聊查询正常、身份正确。

本地回归覆盖个人凭据引用、延迟启动 Stream、重复实例与端口冲突、重启恢复、企业配置校验与 Profile 诊断。浏览器检查使用真实组件和模拟传输，覆盖表单对齐、密码清空、企业连接无地址输入及窄屏布局。

本轮没有把 Web 验收视为 Desktop 壳验收，也没有把自动化路由测试视为企业服务器多用户实测；这两项仍待对应环境验证。
