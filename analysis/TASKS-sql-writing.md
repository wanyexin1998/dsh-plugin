# dsh-data-ide 手写 SQL 流畅度：可落地验收任务清单（v1）

> 来源：`analysis/SQL-writing-first-principles.md`（第一性原理、三处结构性断裂、优化/新增清单）。
> 用法：每条任务独立可交付、可验收；**一次只领一条**，完成即勾掉。任务按批次排序，批次内按依赖排序。
> 编号规则：`SQL-0xx`（B0 准备）、`1xx`（B1 执行与止血）、`2xx`（B2 记忆与表达）、`3xx`（B3 双模式与验证）、`4xx`（B4 收割与结对）、`5xx`（验收与文档）。
> 标记：**⚑** = 需要用户拍板；**S** ≤0.5 天、**M** ≤2 天、**L** >2 天（含测试；按本仓结构估算）。

## 0. 全局完成定义（每条任务都适用）

1. **测试**：先写失败用例；新增/修改逻辑单测覆盖，维持 **per-file 100%**；UI 事件用例按 `pointerdown → pointerup → click` 真实序列。
2. **文档**：交互/契约变化同步 `docs/03`（交互）、`docs/05`（MCP 契约，若涉及）、`docs/09`（待办）、`docs/07`（里程碑）、`docs/00 §9`（变更记录）。
3. **不回归**：AC-1~AC-8 全绿；`pnpm precommit`（bundle / vitest / coverage / 硬编码色 / 跨包 import）通过。
4. **可验收**：每条至少有一个**可执行验收**（单测断言或 smoke 步骤-期望）；UI 任务额外把 smoke 步骤写进 `docs/testing.md`。
5. **不改边界**：不引入 `@deepseek-ai/*` peerDeps / value import；注册走 `ctx.effect`；密码/token 不入日志。

## 4. B1 执行语义与止血（P0 核心，1–2 天）

### SQL-101 语句边界定位纯函数
- **优先级/成本**：P0 / S ｜ **依赖**：无 ｜ **改动面**：`src/execute/split.ts`（或新 `src/execute/statement.ts`）
- **目标**：给定文档与光标 offset，返回 `{index, start, end, text}`；复用字符串/注释感知扫描器。
- **验收**（单测文件 `tests/statement-at-cursor.spec.ts`）：
  1. `SELECT 1; SELECT 2; SELECT 3` 光标在 `SELECT 2` 内 → 返回第 2 条；
  2. 光标在两条之间的空白/注释 → 明确规则（建议：取右侧最近语句；无右侧取左侧最后一条），有单测断言；
  3. `SELECT * FROM t WHERE a = 'x;y'` 光标在 `y` 后 → 仍返回整条；
  4. 反引号/`--`/`#`/`/* */` 内的 `;` 不切；
  5. 末尾无分号/空语句/只有注释 → 返回 null 或空语句规则用单测锁死。

### SQL-102 `Ctrl+Enter` 执行光标所在语句
- **优先级/成本**：P0 / M ｜ **依赖**：101/103 ｜ **改动面**：`editor-cm.ts`、`SqlEditor.tsx`、`SqlWorkbenchPanel.tsx:885-896`、`docs/03`
- **目标**：编辑器把光标 offset 交给面板；无选区时用语句定位执行；有选区仍最高优先。
- **验收**：
  1. 单测/组件测：3 条语句脚本，光标在第 2 条 → `api.execute` 收到的 SQL 只含第 2 条；
  2. 光标在多语句上但无分号 → 按 §101 规则执行；
  3. 有选区且跨 2 条 → 只执行选区（现有行为保持）；
  4. 手动 smoke：3 条脚本改第 2 条、`Ctrl+Enter`，只出第 2 条结果，第 1/3 条结果不刷新；
  5. 工具栏 `title` 与 ⓘ 提示同步为「执行光标语句」。

### SQL-103 单条选区 bug + `firstStatement` 修复
- **优先级/成本**：P0 / S ｜ **依赖**：101 ｜ **改动面**：`SqlWorkbenchPanel.tsx:885-896`、`execute/core.ts:238-242`

## 7. B4 收割与结对（2–3 周）

### SQL-401 导出 INSERT/JSON（B8）
- **优先级/成本**：P1 / S ｜ **依赖**：无 ｜ **改动面**：`grid.ts`、`ResultGrid.tsx:297-306`
- **目标**：导出菜单增加 INSERT 语句与 JSON（与当前筛选/排序结果一致）。

### SQL-402 结果→SQL + 复制列清单
- **优先级/成本**：P1 / M ｜ **依赖**：无 ｜ **改动面**：`ResultGrid.tsx`、`grid.ts`、剪贴板
- **目标**：选中单元格/行 → 复制为 `WHERE col IN (...)`、`INSERT INTO … VALUES …`、`UPDATE … SET …`；复制列名清单（`col1, col2`）。
- **验收**：
  1. 选中 1 列多行 → `WHERE col IN ('a','b')`；
  2. 选中行 → INSERT 骨架（表名取结果 tab 主表名，取不到则占位）；
  3. 复制列清单可指定别名前缀；
  4. 单测：转义/NULL/数值。

### SQL-403 参数化查询
- **优先级/成本**：P1 / M ｜ **依赖**：无 ｜ **改动面**：`split.ts` 或新 `params.ts`、编辑器装饰、参数条组件
- **目标**：`:` 命名参数占位 + 参数条（记住上次值；缺值才提示，不每次弹模态）；生成可执行 SQL。
- **验收**：
  1. `WHERE dt = :dt` 出现参数条，填值后执行替换后的 SQL；
  2. 参数值持久化到该 SQL（历史/收藏）；
  3. 缺值提示，不静默替换；
  4. 单测：解析/替换/转义（防注入）。
- **备注**：DBeaver「每次弹参数框」是反面案例，默认不弹模态。
